# 自定义宠物生成

本文说明如何让用户上传自己宠物的几张照片，生成一套与现有动画系统兼容的像素桌宠，并像内置宠物一样选用。实现范围以 macOS 先行；Windows 在本文给出文件格式和移植要点，不在第一期改动 Windows 运行时。

现有六款宠物保持不变。飘飘仍是默认角色，团团、豆豆、斑斑、桃桃、木木继续使用原来的精灵表。已经放在 `~/Library/Application Support/PiaoPal/Sprites/` 里的自定义 GIF 继续按原逻辑加载。

## 背景：飘飘是怎么做出来的

飘飘不是模型一次吐出就能用的成品。`artwork/piaopal/` 里的记录说明实际流程是：

1. 用真实猫咪照片做身份参考，用已确认的像素风格做风格参考。
2. 先要一张角色图，再按格子生成或修补动作。
3. 一次生成整张 8×4 图集会把朝向、睡觉朝向、描边和透明度画错。NW 与睡觉格后来用补丁替换，斜向四帧步态又按方向单独重画了多轮（`motion-v4/`、`motion-v5/`）。
4. 程序不做“补腿”或抠图。`Tools/PreparePiaoPalAssets` 和 `Tools/PreparePiaoPalWalk` 只做裁切、统一缩放、按锚点平移和镜像，保留裁切范围内的透明度。
5. 主图集是 512×256、8 列 4 行、每格 64px，32 格正好对应 `Engine/Simulation/PetMotion.swift` 的 `spriteSets`。步态表是 256×512、4 列 8 行，行序为 N、NE、E、SE、S、SW、W、NW，与 `PetAnimationTiming.walkingDirections` 一致。锚点是格子内墨水包围盒的水平中心和底部，输出锚点为 `(32, 60)`。

自定义宠物沿用这条已经验证过的分工：**模型只负责画一只风格稳定的动物，程序负责摆进现有格子。**

## 用户流程

入口有两处，打开同一个“我的宠物”窗口：

- 设置里现有皮肤网格下方，与“浏览皮肤”并列。
- 皮肤市场窗口顶部。

流程：

1. **准备密钥（只需一次）。** 用户选择图像服务、填写 API 密钥、可选的模型名和接口地址，保存密钥。密钥进钥匙串，不进偏好文件，不进日志，不进仓库。
2. **上传 3–5 张照片。** 用系统文件选择器选取 JPEG、PNG、HEIC、WebP、GIF 或 TIFF。不申请照片图库权限。读入内存后立刻结束安全作用域访问。
3. **质量检查。** 不合格的照片标出原因（太小、太糊、几乎纯色、比例过长、无法解码、超过张数）。全部通过后才能生成。
4. **命名。** 显示名 1–24 个字符，只影响界面，不改变已有的宠物昵称（`pet_name`）。昵称仍然是用户给“当前这只桌宠”起的名字。
5. **生成。** 显示进度（参考图，然后每一帧）。可取消。费用估算显示在按钮旁，按所选画质和帧数计算，并注明以服务商当时标价为准。
6. **预览。** 展示待机格放大图和整张图集。自动校验没通过的帧会在次数用尽后停在这里，并说明哪些帧失败。
7. **重试。** “只重试失败帧”保留已经通过的图，不重新花钱生成成功帧。“全部重来”清空本轮结果。
8. **保存。** 写入自定义精灵目录，立刻出现在设置的皮肤网格里并选中。之后离线可用。
9. **重命名 / 删除。** 在“我的宠物”列表里操作。删除会去掉图集、步态表和清单项；若删的是当前宠物，切回飘飘。内置六款不能删、不能被同名文件覆盖。

取消或失败不会写入半成品，也不会改 `selected_skin`。

## 照片预处理与质量检查

全部在本机完成，不上传原图到维护者的服务器。

| 检查 | 规则 | 不过时 |
| --- | --- | --- |
| 类型 | ImageIO 能解出一张位图 | 拒绝 |
| 体积 | 单张不超过 25MB | 拒绝，避免超大图占满内存 |
| 尺寸 | 短边至少 256px | 拒绝。桌宠只有 64px，但身份参考需要眼睛、花纹和鼻子 |
| 比例 | 长边 / 短边不超过 3 | 拒绝全景条和过窄截图 |
| 清晰度 | 缩到约 64px 后的拉普拉斯方差低于阈值 | 视为过糊 |
| 内容 | 亮度标准差过低 | 视为近乎纯色，没有主体 |
| 张数 | 3 到 5 张都合格 | 少了不够身份，多了增加费用且没有更多格子收益 |
| 方向 | 按 EXIF 转正 | 生成端看到的是正过来的动物 |
| 隐私 | 重绘成 PNG，不拷贝 EXIF、GPS 或颜色配置文件 | 上传内容只有像素 |

合格照片的长边缩到 1024px 以内，使用高质量插值。这一步只服务于上传，不直接当精灵。

阈值写在代码里，并用合成图固定下来：纯色图必须失败，带清晰色块边缘的图必须通过，带自定义文本块的 PNG 重编码后不能再含那段文本。

## 生成策略

**先角色参考图，再逐帧，最后由程序拼图。** 不让模型直接交 8×4 或 4×8 的生产图集。飘飘的返工记录说明模型会画错朝向、把格子画歪、在透明区涂上棋盘格或色边。逐帧生成更贵，但每一帧可以单独重试，拼图结果可复现。

### 第一步：角色参考图

一次请求，附上全部合格照片。要求：

- 同一只动物的转身参考：正面、左侧、右侧、背面，外加一张四分之三。
- 像素风格：硬边色块、有限配色、深色描边，不要抗锯齿晕边，不要文字、地面和阴影。
- 背景是真正的透明，不要画棋盘格。
- 物种、毛色、花纹、眼睛、耳朵和尾巴以照片为准。动作槽是为四足动物准备的（见下），但身份不能被画成另一只猫。

参考图只在内存里使用，用来约束后续每一帧。不写入磁盘，避免多留一份从照片派生的图像。

### 第二步：按动画槽逐帧

每一帧单独请求。参考图加上最多两张原照片作为输入图像。提示词写明这一格的朝向和姿势，并重复透明度、边距和“不要画字”的约束。

姿势词汇和现有 17 个状态对齐：

- 八个方向的行走（面朝画面上方为离开观察者，下方为面向观察者，左右为侧面，斜向为对应的四分之三）。
- 坐下待机、警觉、犯困。
- 用后脚挠自己。
- 四个方向的直立挠墙（不画墙）。
- 蜷着睡觉的两帧，只有轻微起伏，朝向相同。

勾选“四帧步态”时（默认开启）：八个方向各生成 4 帧，写入步态表。主图集里该方向的两帧取步态的第 0 帧和第 2 帧，这样旧的两帧循环也不会播到同一张图。关闭时只生成主图集需要的两帧行走，宠物用原来的 legacy 步态，和团团等角色一样。

帧数：

| 方案 | 参考图 | 非行走动作 | 行走 | 合计 |
| --- | --- | --- | --- | --- |
| 含四帧步态（默认） | 1 | 16 | 32 | 49 |
| 仅主图集两帧行走 | 1 | 16 | 16 | 33 |

非行走 16 帧的组成：待机、警觉、犯困各 1，挠自己 3，四面挠墙各 2，睡觉 2。

同一组里的帧共用提示词里的身份描述，但每帧的姿势句不同，避免模型交回两张相同的图。组的划分是：每个行走方向、睡觉、挠自己、每一面挠墙。不同组之间不要求身高一致（睡觉本来就更矮）。

### 第三步：确定性拼图

对每一张生成图：

1. 用 alpha 找到墨水包围盒。碰到源图边缘视为可能被裁掉，该帧失败并重试。
2. 全角色共用一个缩放，取“每帧都能放进格子内约 52px”的最小缩放，最近邻，不单独把某一帧拉满格子。
3. 水平中心对齐到格子的 x=32，墨水底部对齐到 y=60。这与 `crop-manifest.json` 的锚点约定相同。
4. 输出：
   - `{id}.png`：512×256，8×4，64px，格位与 `spriteSets` 一一对应。
   - `{id}-walk.png`（开启步态时）：256×512，4×8，64px，行序与 `walkingDirections` 一致。

程序不补像素、不镜像造新动作、不去背。模型没画透明，就重试，而不是在本地猜背景。

现有动画系统的限制需要在界面上说清楚：挠痒、蜷睡和八方向走是按猫科桌宠设计的。狗或类似四足动物可以生成，鸟、鱼、只露出脸的照片会勉强填进这些姿势。模型必须画照片里的那种动物，不能默认画成飘飘。

## 图像模型与接口

**默认服务：OpenAI Images API，模型 `gpt-image-1`，调用 `POST /v1/images/edits`。**

选择它，是因为它和飘飘这条流水线的形状一致，并且精灵图缺不了的两点它都有：

- 一次请求可以带多张参考图（照片，以及后来的角色参考图）。
- `background=transparent` 和 `output_format=png` 能要求真正的透明 PNG。主图集和步态表都依赖格子边缘透明；Metal 用预乘 alpha 混合，不接受画进去的棋盘格。
- 用户自己的 API 密钥是正式用法，不需要再包一层 SDK。
- 画质分 `low` / `medium` / `high`。像素最终会最近邻缩到 64px，默认用 `medium`：比 `low` 更不容易把五官涂糊，又比 `high` 便宜。用户可以改。

模型名和 Base URL 做成设置项。服务商更换模型 ID，或用户使用兼容的 HTTPS 代理时，不用改代码。只允许 `https`，以及 `http://127.0.0.1` / `http://localhost` 上的本地兼容接口，避免密钥发到任意明文地址。

不采用的方案：

| 方案 | 原因 |
| --- | --- |
| 让模型一次输出整张图集 | 飘飘已经证明格位、朝向和透明度不可靠，失败时必须整张重画 |
| 只做本地扩散模型 | 32 帧以上的身份一致性需要额外微调和数 GB 权重，不适合这个桌面应用的体积；可作为以后的离线选项 |
| Google Gemini 图像模型作为第一期唯一实现 | 身份一致性好、往往更便宜，但透明背景不如 Images API 稳定。接口留成可替换，后续可以加第二种提供方 |
| 专门的像素画模型（如 Recraft）单独作为默认 | 像素风格强，多张照片锁身份较弱。参考图流程更依赖“看图改图” |

价格会变。按撰写时 OpenAI 公开的 `gpt-image-1` 1024 档大约估计：low 约 $0.011/张，medium 约 $0.042/张，high 约 $0.167/张。默认 medium、含四帧步态，约 49 次请求，大约 2 美元量级；只做主图集大约 33 次。参考图可用 1536×1024，单帧用 1024×1024。界面上的金额是估算，不是报价，也不代扣。

## 生成放在哪里

**建议：用户自备 API 密钥，应用直接请求所选服务商。第一期不设托管后端。**

| | 应用直连（采用） | 小型托管后端 |
| --- | --- | --- |
| 费用 | 用户向服务商付自己的用量。维护者不垫付，也不做计费 | 需要配额、账单和滥用防护，否则会被公开刷接口 |
| 隐私 | 照片和参考图只发给用户选择的服务商。本应用不落盘照片，不经过飘伴的服务器 | 多一跳。即使用户同意，维护者也会接触到宠物照片 |
| 滥用与审核 | 没有可被匿名调用的飘伴接口。服务商自己的审核仍然生效；审核拒绝不自动重试 | 必须做登录、速率限制和内容审核，否则密钥会泄露在后端 |
| 离线 | 生成时需要网络。保存之后的图集完全离线，和内置宠物一样 | 生成同样不能离线，还多一个服务可用性依赖 |
| 密钥 | 钥匙串。仓库、日志、崩溃文本里都不能出现 | 后端密钥要轮换、分发和审计 |

托管后端只适合以后真的要做“不用密钥、按次付费”的时候。那是另一个产品决定，不应该挡在第一期前面。

审核失败（响应里出现 moderation / safety 一类代码）停下来告诉用户，不换提示词硬重试。429 和网络错误可以重试。HTTP 正文里的错误信息可以显示，但要先去掉密钥本身；日志只记状态码和帧 ID。

## 输出格式

自定义宠物 ID 形如 `custom-` 加一段字母数字（保存时用 UUID）。ID 不能是六款内置 ID，不能是 `ai-preview`，不能含路径分隔符。

目录仍是 `~/Library/Application Support/PiaoPal/Sprites/`：

```text
custom-<id>.png           512×256 主图集
custom-<id>-walk.png      256×512 步态表，可没有
custom-pets.json          清单
```

清单：

```json
{
  "schema_version": 1,
  "pets": [
    {
      "id": "custom-…",
      "display_name": "咪咪",
      "created_at": "2026-11-12T00:00:00Z",
      "atlas_file": "custom-….png",
      "walk_atlas_file": "custom-….png",
      "cell_size": 64,
      "provider": "openai",
      "model": "gpt-image-1",
      "includes_walk_atlas": true
    }
  ]
}
```

`walk_atlas_file` 在没有步态表时省略。先写 PNG，再原子替换清单。若清单损坏或落后于文件，加载时把目录里多出来的 `custom-*.png`（排除 `*-walk.png`）补进列表，显示名先用 ID，避免用户文件被忽略。

加载规则：

- 飘飘仍只读包内的 `piaopiao.png` / `piaopiao-walk.png`。
- 其他 ID：自定义目录里的同名 PNG 优先于同名 GIF，GIF 优先于包内资源。今天的自定义皮肤只有 GIF，行为不变。
- `*-walk.png` 不是可选宠物。只有主图集加载成功且步态表恰好为 256×512 时，才作为该 ID 的四帧步态。
- 有步态表的自定义宠物使用与飘飘相同的运动配置（按位移推进的四帧步态，待机和睡觉保持原画并轻微呼吸）。没有步态表的自定义宠物，包括旧 GIF，继续用原来的两帧时间轴。内置的团团等角色没有步态表，仍然是原来的运动。

## 自动校验与重试

每一帧最多 3 次。失败原因写进下一次提示词（更小、留边、真透明、不要棋盘格、姿势必须和上一张不同）。次数用尽则整只宠物不保存。

| 检查 | 对象 | 失败则 |
| --- | --- | --- |
| 能解码成一张图 | 单帧 | 重试 |
| 四角和边缘不是不透明背景；不透明像素占比不能高到像一张铺满的底 | 单帧 | 重试。不在本地抠图 |
| 有足够墨水，且包围盒不贴源图边缘 | 单帧 | 重试 |
| 同一组内两帧像素不能相同，行走相邻帧至少有一小部分像素不同 | 组 | 重试较新的那一帧 |
| 同一组墨水高度相差不超过约 15% | 组 | 重试离群帧 |
| 拼好的主图集为 512×256，步态表为 256×512 | 整表 | 视为程序错误，不重试模型 |
| 每格边缘 alpha 接近 0，不透明像素落在空格和满格之间 | 每格 | 对应帧重试 |
| 32 个主格都被占用且与 `spriteSets` 一致；步态 8×4 帧都存在 | 整表 | 缺的帧重试 |

步态检查能发现“两帧一样”和“忽大忽小”。它不能证明哪只脚着地。飘飘的着地问题是人工看的（见 `docs/animation-review.md`）。第一期不把自动校验说成足锁通过。

## 保存、导入与选用

保存成功后立刻把纹理交给现有的 `SkinManager`，并选中该 ID。设置网格、菜单栏切换和 `selected_skin` 都走原来的路径。重启时 `loadCustomSprites` 会再次读入 PNG 和 GIF。

重命名只改清单里的 `display_name`。删除同时卸下纹理。若删的是当前选择，先切回飘飘再删文件。

市场下载的 GIF、成就里的六款内置 ID、引导页里的六选一，都不读取这份清单，因此不受影响。

## 平台范围

**第一期只做 macOS 13+。** 照片选择、预处理、钥匙串、生成、拼图、校验、保存和设置/市场入口都在 Mac 应用里。

Windows 现在从安装目录读取六款内置图，没有自定义精灵目录（见 `docs/windows.md`）。要使用同一只自定义宠物，需要：

- 读取 `%LOCALAPPDATA%\PiaoPal\Sprites\` 里的同一套 PNG 和 `custom-pets.json`。Mac 上生成的文件拷过去就能用，不必在 Windows 上重新生成。
- 主图集按 8×4 采样，步态表按 4×8、且仅在 `includes_walk_atlas` 时使用飘飘那套运动配置。
- 设置里增加列表、重命名和删除。生成 UI 可以再后做。
- 密钥放 Windows 凭据管理器，不要放 `settings.json`。
- Swift 生成代码不能直接复用，但清单字段、格位和校验规则应与本文一致，避免两套格式。

在 Windows 移植完成之前，自定义宠物是 Mac 功能。不要在 Windows 设置里放一个会失败的入口。

## 本地化

新增文案至少覆盖现有七种语言：简体中文、繁体中文、English、Français、日本語、Deutsch、Español。格式占位符的顺序在各语言里保持一致。

宠物显示名是用户输入，不翻译。内置六款的名字不变。服务商返回的英文错误可以附在本地化句子后面，作为细节，不替代本地化说明。

## 失败时用户看到什么

| 情况 | 行为 |
| --- | --- |
| 照片不合格 | 停在选择页，逐条说明，不发请求 |
| 没有密钥或地址不合法 | 不发请求，指出要填写的项 |
| 取消 | 停在当前步，已成功的帧留在内存里，可以继续重试其余帧 |
| 网络、超时、429 | 该帧重试，直到次数用尽 |
| 审核拒绝 | 停止，说明内容未通过服务商审核，不自动改词重试 |
| 单帧校验失败 | 只重画该帧 |
| 次数用尽 | 不保存。预览页列出失败帧，可再试这些帧 |
| 磁盘写入失败 | 不改当前宠物，提示保存失败 |
